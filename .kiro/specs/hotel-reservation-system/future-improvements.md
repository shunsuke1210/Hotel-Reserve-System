# 今後の改修（MVP の対象外）

MVP では実装しないが、後で検討する項目をまとめる。要件定義の中で出てきたもの、および要件を整理する中で見つけた懸念を記録する。
「関連」の ID は brief.md の項目（RS-09a など）を指す。

最終更新：2026-10-16

## 今後の改修の項目

| ID | 項目 | 内容 | 関連 |
|---|---|---|---|
| FI-01 | 年齢区分の精度 | 同行者は自己申告のため、12歳の小学6年生と中学1年生を区別できない。同行者の生年月日の入力を検討する（会員本人は 2026-10-20 に学年で判定すると決定。brief.md DT-M3） | RS-09a |
| FI-02 | OTA 連携 | 楽天トラベル、じゃらん、Booking.com などとの在庫・予約の連携 | BG-03 |
| FI-03 | 管理者メニュー | 各種設定、スタッフのアカウント管理、機械翻訳の編集、返金・免除・料金の手動変更、操作履歴の閲覧、売上・稼働率の集計。それまでは初期データを開発者が直接書き換える | BG-04 |
| FI-04 | 部屋ごとの人数指定 | 入力が手間なので、MVP では予約全体の人数だけを入力する。部屋ごとの人数が分かれば、1名1室利用の料金、部屋ごとの名簿、割り当ての精度を改善できる | RS-08, PR-13a |
| FI-12 | カード保証の有効性 | 予約したときにカードが使えるかの確認（与信）や、宿泊までにカードの有効期限が切れる場合の扱い。キャンセル料を請求できないおそれがある。与信の確認には決済代行サービスとの通信が必要で実装が大きくなるため、今後の改修とする（2026-10-16 確認） | PY-02 |
