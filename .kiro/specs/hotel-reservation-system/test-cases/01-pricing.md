# テストケース：料金・暦・税

対象：要件 6.1〜6.19（料金の計算）、3.7（検索結果の料金表示）、17.1・17.2（特定期間割増）、21.7（設定を変えても確定済みの料金を変えない仕組み）。あわせて design.md の BusinessCalendar（営業日・暦の日付・割増の対象日・早期割の期限・無料キャンセル期限の算出）、宿泊税、朝食、時間外、料金の控え（作り方と固定）を確認する。

範囲外（別の担当）：検索 API の入力検証、キャンセル料の判定、予約変更の流れ全体（差額・返金など）、画面操作。

ケース数：190件（重複のため11件を削除した。削除したケースは 5章）

## 1. テスト観点

### 正常
- 初期データ（料金の版1・基本料金・基準人数）で、客室タイプ・年齢区分ごとの税込み単価が design.md P-01 の整数計算どおりになる
- 割増と割引（人数割・連泊割・早期割）を合算して1回だけかける。要件 6.19 の計算例（大人 21,500円・子ども 10,700円・合計 61,900円・宿泊税 600円）を再現する
- 朝食（区分ごとの人数・全泊に同じ人数・子ども半額・幼児無料・率をかけない）、時間外（1室1時間1,000円・常に現地精算）、宿泊税（幼児を含む1人1泊ごと）の明細ができる
- 暦の関数：営業日、暦の日付、割増の対象日、早期割の期限、無料キャンセル期限を正しく返す
- 特定期間割増をフロント以上が登録・変更・削除できる
- 検索結果に、税込みの宿泊料金と、別枠の宿泊税を返し、表示する。金額は日本円の税込み額で表示する

### 異常
- 朝食の人数が区分の人数を超えると VALIDATION_FAILED
- 時間外の時刻が選択肢（アーリー 12・13・14時、レイト 13・14・15時）にないと VALIDATION_FAILED（03 の TC-RS-083・086・087・090 で確かめる）
- 予約者が宿泊する予約で、予約者の年齢区分の人数が0だと VALIDATION_FAILED
- 特定期間：開始日 ＞ 終了日、率が範囲外、ほかの期間と重なる、清掃員による登録を断る（清掃員による登録は 02 の TC-MB-189 で確かめる）

### 境界
- 営業日の 0:59／1:00／1:01、暦の日付の 23:59／0:00（日本時間と UTC の違いを含む）
- 曜日（木／金、土／日）、祝前日と祝日当日、振替休日・国民の休日・連休の最終日
- 特定期間の開始日・終了日とその前後、割増の重なり（特定期間の率が曜日割増より低い・同じ・高い）
- 早期割の期限（同じ日がない月・うるう年・年またぎ）と、期限当日の 23:59／翌日 0:00／翌日 1:00 の予約
- 判定人数の段階の境目（1／2、3／4、9／10）、連泊の段階の境目（1／2、4／5）
- 率の下限（−49%／−50%／−51%、割増を含めた合算）
- 100円未満の切り捨ての順番と、小数を使わない整数計算
- 宿泊税の境目（4,999／5,000／5,001円、19,999／20,000／20,001円）と、税抜単価の端数
- 特定期間の率（0／1／100／101%）と、期間の隣接・重なり
- 年齢区分の判定日（チェックイン日）と誕生日の前後、学年の境目（4月1日／4月2日生まれ。DT-M3）

### 連携
- 祝日データ・特定期間割増・料金の版 → 夜の控え → 料金計算 → 見積もり・検索結果
- 早期割の期限と、予約に追加した夜の控え（ADR-15。04 の TC-CH-045〜047 で確かめる）
- 会員の生年月日と、名簿の予約者の行の年齢区分
- 時間外の料金の版：PriceCalculator は時間外の入力で渡した、選んだ時点の版（earlyCheckinRate・lateCheckoutRate）の単価で計算する（L-34）。予約のときからある時間外の明細は、後で新しい版の夜を足しても額と版（rate_version_id）を変えない（L-14）
- 後から加えた朝食の料金の版：PriceCalculator は、後から加えた分（addedLater）を、入力で渡した加えた時点の版の単価で計算し、夜の控えの版を使わない（L-45）

### 状態遷移
- 特定期間割増の登録 → 変更 → 削除の各時点で、新しい予約と確定済みの予約の料金
- 料金の版の追加（版1 → 版2）の前後で、新しい予約と確定済みの予約の料金・控え・明細の版（時間外を含む）
- 確保（決済待ち）から確定までの間に設定が変わった場合（確定の時点の設定で計算し直し、確保の時点の額と違えば PRICE_CHANGED で確定しない。brief.md PY-06a、要件 4.24）

## 2. テストケース

**共通前提**（前提条件の欄の「共通」）
- 現在＝2026-11-10 10:00（火・日本時間）。時刻はすべて日本時間（UTC と書いたものを除く）
- 初期データ：料金の版1（曜日割増 2000bp、人数割 2名 500・4名 1000・10名 1500bp、連泊割 2泊 1000・5泊 2000bp、早期割 1000bp、下限 −5000bp、消費税 1000bp、朝食 3,500円、時間外 1時間 1,000円、宿泊税 5,000円未満 0円・20,000円未満 200円・それ以上 500円）。基本料金はスタンダード 15,000円、デラックス 18,000円、プレミアム 23,000円、スイート 40,000円、金沢スイート 70,000円。基準人数は全タイプ2
- holidays：内閣府「国民の祝日」の一覧（振替休日・国民の休日を含む。2026〜2027年分）。特定期間割増の登録なし
- 支払い方法は事前決済、朝食・時間外なし、客室タイプはスタンダード キング（それぞれ記載がある場合を除く）
- 「仮の版」「仮の基本料金」と書いたものは、計算方法を確かめるための値で、初期データではない

**記法**
- 税込み単価 ＝ ⌊単価のもと ×（10,000＋率）× 11 ÷ 10^7⌋ × 100（design.md P-01 手順3。10^7 ＝ 10,000,000）。「率」は合算した後の bp（1% ＝ 100bp）
- 宿泊税の判定は、税抜単価（単価のもと ×（10,000＋率）÷ 10,000。切り捨て前）を区分の境目と比べる（P-01 手順7）
- 対象機能が PriceCalculator.calculate のケースは、前提条件と入力から決まる夜の控え（NightSnapshot：版・基本料金・割増率・早期割の対象）を渡す単体の確認。「予約の見積もり」は POST /reservations/quote を使い、控えの作成から料金計算までをまとめて確認する
- 時間外を選ぶ PriceCalculator.calculate のケースでは、時間外の入力（PriceInput.offHours）に、選んだ時点の料金の版（earlyCheckinRate・lateCheckoutRate）も渡す（design.md PriceInput、設計の補足 L-34）。記載がなければ版1（1時間 1,000円）を渡す
- 後から加えた朝食を含む PriceCalculator.calculate のケースでは、PriceInput.addedLater に、加えた分（breakfastCounts の内数）と加えた時点の料金の版を渡す（design.md PriceInput、設計の補足 L-45）
- 金額の期待値は、手計算と、P-01 の式を独立に書いた検算用の計算の2回で確かめた
