## 1. テスト観点

**正常**
- 会員（G15）とフロント（F07）が、日程・人数・室数・オプションを変更でき、同じルールで差額を精算する。滞在中の延長・早期チェックアウトはフロントだけが行う
- 追加した夜・人・オプション（朝食・時間外）は変更時点の料金の版で、もとの夜は予約時の控えで計算する。人数割・連泊割は最終の人数・泊数で段階を決め、率は各夜の版のものを使う
- 減らす変更と早期チェックアウトは部分キャンセルとして、変更時点のキャンセル規定で計算する。オプションを減らすだけの変更はキャンセル料なしで返金する
- 個人のキャンセル料：期限前は0円、期限後は「取り消した部屋・人の、取り消した最初の夜」の宿泊料金（税込みの表示額）
- 団体のキャンセル料：段階の率を、取り消した分の宿泊料金の総額（朝食・時間外・宿泊税を除く）にかける（日程の変更・早期チェックアウトも同じ）
- 早期割を適用した夜の宿泊料金と宿泊税は、キャンセル・減らす変更・ノーショーのどれでも返金しない（朝食は返金する）。早期割の予約でも、早期割なしの料金で加えた夜は個人・団体の規定で計算する
- 出発日を変えずに到着日の前に夜を足す変更は、夜の追加（延長）として扱う（早期割の予約は足した夜だけを早期割の条件で判定し、早期割でない予約もキャンセル料をかけない）
- 日程の変更では、もとの夜に当てるキャンセル規定（個人の期限・団体の段階）をもとの到着日を基準に判定する。今の部屋が新しいすべての夜に空いていればその部屋のままにし、空いていなければ自動の割り当てで選び直す。室数を増やすときの追加の部屋は今の部屋と同じ階を優先する
- 事前決済はその時点でカードに決済・返金する。現地払いは精算額に反映し、チェックイン前に発生したキャンセル料・ノーショー料は登録カードに請求し、チェックイン後に発生したキャンセル料（早期チェックアウト）は現地で精算する
- カードへの請求が断られても、キャンセル・ノーショー・現地払いの変更（減らす変更・日程の変更）は確定し、未回収として「対応が必要な一覧」に出し、支払いのお願いのメールを作る。振込の入金の記録で未回収が減る
- 団体のノーショーは全泊の宿泊料金の100%をノーショー料とし、2泊目以降も返金しない
- ノーショーで返金するのは、取り消した2泊目以降の夜の宿泊料金と宿泊税だけ（早期割を適用した夜・団体を除く）。前の変更で確定したキャンセル料は返金しない
- ノーショーの取り消しで滞在が短くなったら連泊割を最終の泊数で計算し直す。2室以上の予約は、全室を戻せる夜までをそろえて戻す。団体と早期割の予約で戻せなかった夜は、宿泊料金と宿泊税を返金する。故障中の期間に入る夜も戻し、警告の一覧に出す
- 宿泊税は宿泊料金が返金される夜だけ返金する（P-06 の例）。返金しない宿泊税はキャンセル料・ノーショー料の区分に付け替える
- 変更完了・キャンセル完了・ノーショー料などの請求・返金完了のメールを作る。早期割の予約のノーショーの請求のメールは、請求額を1泊目のノーショー料とし、返金しない2泊目以降の宿泊料金と宿泊税を別の行で示す

**異常**
- 定員・室数・予約期間・朝食の人数の条件を満たさない変更
- 延ばす夜に同じ部屋が空いていない（ほかの予約・故障中・複数室のうち1室）。室数を増やす・日程の変更で部屋を割り当てられない（NO_AVAILABILITY）
- 追加の決済が断られる・決済サービスの障害・返金の障害（何も確定しない）。追加の決済が決済サービスの障害のときは、決済の行を PENDING のまま残し「決済の照合待ち」に出す。ノーショーの返金の障害では判定を確定し、「返金待ち」にする
- 見積もりの後に予約が変わった・時刻が過ぎてキャンセル料が変わった（QUOTE_OUTDATED）、確定の二重送信
- 権限のない役割・他人の予約・変更できない状態・キャンセルできない状態（状態の誤りと見積もりの古さが同時なら状態の誤りを返す）
- ノーショーの延長の期限が範囲外（VALIDATION_FAILED）

**境界**
- 個人の無料キャンセル期限（到着日 15:00 の48時間前の 14:59／15:00／15:01）
- 団体の段階（30日前・7日前・前日の 0:00 の、1分前／ちょうど／1分後）
- 早期割の予約に夜を追加した日（期限の日の 23:59／翌日 0:00／0:01）
- 定員ちょうど、室数＝大人の人数、予約期間（今日＋365日／366日）
- 団体の判定（4室と5室、出発日は夜に含まない、夜ごとの合計が4室、合算の対象の状態）
- ノーショーの判定（営業日の境目 0:59／1:00／1:01）、延長の期限（2:45／3:00／3:15）、延長の下限（到着日の25:00 ちょうど／25:01）、延長の上限（翌日 11:59／12:00／12:01）、ノーショーの取り消しの期限（出発日のチェックアウト時刻の1分前／ちょうど）
- 1泊だけの予約のノーショー、ノーショーの取り消しで戻せる夜の範囲（1泊だけ・一部の夜まで・複数室の一部だけ戻せない）
- 減らした最初の夜が割増の夜、最初の夜の料金が予約の1泊目と違う場合（変更で1泊目が入れ替わった予約のノーショーを含む）
- 日程の変更のキャンセル規定の基準日（もとの到着日と新しい到着日で、期限・段階の判定が分かれる場合）

**連携**
- 料金計算（P-01）との連携：再計算後の残りの夜の料金とキャンセル料の組み合わせ
- 在庫（room_nights）：キャンセル・ノーショーで在庫に戻る、延長・復元で同じ部屋を使う。料金の控え（stay_night_prices）の有効な行は各夜1行
- 決済代行（模擬）：CHARGE・REFUND・FEE_CHARGE の記録
- メール（mail_outbox）：RESERVATION_CHANGED・RESERVATION_CANCELLED・FEE_CHARGED・REFUND_COMPLETED・PAYMENT_REQUEST
- 団体の判定（P-08）とキャンセル料の連動、部屋の状態（来客なし）とノーショーの取り消し後のチェックイン
- 警告の一覧（未回収・返金待ち・決済の照合待ち・故障中の部屋に割り当てられた予約。取り消したノーショー料は未回収に数えない）、お知らせ（SPLIT_FLOORS）

**状態遷移**
- CONFIRMED → CANCELLED、CONFIRMED → NO_SHOW → CONFIRMED → CHECKED_IN
- 延長中の予約は 1:00 に判定せず、期限の後に判定する。延長は判定の前の予約だけ、取り消しは NO_SHOW の予約だけ
- is_group は一度 true になったら false に戻らない
- 決済待ち・取消・完了・ノーショー・期限切れの予約は変更もキャンセルもできない。滞在中の予約は、会員は変更できず、フロントだけが延長・早期チェックアウトできる（予約全体のキャンセルはできない）
- 決済の失敗では version が変わらず、同じ見積もりで再試行できる
