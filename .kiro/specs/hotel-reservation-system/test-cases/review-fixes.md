# テストケースの修正の記録

対象：test-cases の 01-pricing.md〜06-integration.md。もとにしたレビュー：review-correctness.md（期待結果の正しさ）、review-questions.md（1章 重複、2章 仕様書で解決できる質問、3章 判断が必要な論点）。

## 修正の方針

- 正しさの指摘 8行・17件はすべて反映した。計算・エラーコード・暦の誤りの指摘はなかった。No.1（TC-CH-046・047）と No.2（TC-CH-074）の主な論点は、2章の Q-PR-02・Q-IT-2 の結論で解決したため、期待結果を残して根拠を書き加えた。No.2 の残り（NOT_CANCELLABLE の対象の状態・HTTP ステータス）は L-1・L-2 で要確認にした
- 作れない前提（末尾 0002・0119 のカード、模擬の障害の設定）は、L-16 の案で書き直した。決済の前に登録するだけのものは「登録はできるが決済だけを断る（例 末尾 0341）／障害にする（例 末尾 0259）カード」、決済済みの予約の追加決済・返金の障害は「テスト用の設定で模擬の応答を切り替える」とした。期待結果は変えていない
- 重複は提案どおり 66組・73件を削除した（うち TC-IT-034 は TC-IT-035 の前提にまとめた）。ID は欠番にし、各ファイルの末尾に「## 5. 削除したケース」を加えた。TC-IT-014 の代わりに、04 に TC-CH-170（完了の予約の G14）を1件加えた
- 2章で解決した質問は、関係するケースの期待結果を結論どおりに直し、4章の質問の行に【解決：…】を付けた。2章が具体的な期待結果を示しているケースは、3章の論点（L-5・L-14・L-3・L-2 など）の影響するケースに挙がっていても、決まった部分を期待結果にし、決まらない部分だけを「要確認（論点ID、元の質問ID）」として残した
- 3章の論点に当たるケースは、期待結果を「要確認（論点ID、元の質問ID）」の形にそろえた。期待結果の一部（エラーコード・HTTP ステータス・保存の応答など）だけが決まらないケースは、その部分だけをこの形にした
- 網羅表は、削除したケースを重複先のケース（別のファイルのものを含む）に書き換えた。削除で 0件になる受け入れ基準はない
