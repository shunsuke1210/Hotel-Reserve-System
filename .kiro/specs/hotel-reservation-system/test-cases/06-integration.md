# テストケース：機能間の連携・状態遷移・同時実行・セキュリティ

機能ごとのケース（01〜05）では確かめにくい、複数の機能や時間の経過をまたぐ動きを確認する。個々の機能の細かい境界値は 01〜05 に任せ、ここでは「つながり」を確認する。

## 1. テスト観点

- **状態遷移**
  - 予約の状態（決済待ち・確定・滞在中・完了・取消・ノーショー・期限切れ）の、許される移り方とその結果
  - 予約の状態の、許されない移り方（取消済み・完了済み・期限切れの予約への操作）と、決済待ちの予約の変更・キャンセルの拒否が確定の後に解けること
  - 1つの部屋の状態が、1泊・連泊・ノーショー・故障中・早期チェックアウトの流れの中で、設計どおりに移ること
- **連携**
  - 予約・変更・キャンセル・ノーショー・移動・故障中の操作が、在庫（空室検索とチャート）に正しく反映されること
  - 予約の作成から精算までの、明細・入金・返金の流れがつながること
  - 定時処理（1:00・9:00・10:00・3:00・毎分・15分ごと・5分ごと）が、前の処理の結果を正しく引き継ぐこと。ノーショーの返金の障害を15分ごとの回で同じ冪等キーで再試行すること（DT-M18）、決済の後の処理が失敗して残った決済を payment-reconcile で照合すること（L-29。決済されていなければ FAILED にする、返金も失敗したら PENDING のまま次の回にもう一度照合する、PENDING になってからちょうど5分00秒の行も対象にする：L-36〜L-38）
- **同時実行**
  - 確保・移動・変更が同時に起きたときに、二重の割り当てや古い見積もりでの確定が起きないこと（予約の延長と別の会員の確保が、同じ部屋・同じ夜を求める場合を含む。延長の側が負けたら EXTENSION_ROOM_UNAVAILABLE：L-39）
  - 同じ確定の要求が2回届いたときに、二重に決済しないこと
- **セキュリティ**
  - 公開用の入口からスタッフ向けの機能に届かないこと
  - 会員どうし、役割どうしでデータが見えないこと
  - カード番号が保存されないこと
